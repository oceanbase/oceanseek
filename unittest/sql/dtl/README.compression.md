# DTL compression configuration and tests

## Configuration contract

`dtl_compress_func` is a dynamic tenant parameter, defaulting to `lz4_1.0`.
Accepted values are `none`, `lz4_1.0`, `snappy_1.0`, `zstd_1.3.8`, and `zstd_1.5.7`.
Names are case-insensitive. ZSTD 1.0, stream,
hardware-specific and other storage-only codecs are intentionally excluded.
The existing `_px_message_compression=false` switch overrides the selection.
`default_compress_func` remains a table-storage setting and is not changed.

Example, executed in the intended user tenant:

```sql
ALTER SYSTEM SET dtl_compress_func = 'zstd_1.3.8';
-- ZSTD 1.5.7 is also available:
ALTER SYSTEM SET dtl_compress_func = 'zstd_1.5.7';
SHOW PARAMETERS LIKE 'dtl_compress_func';
-- Return to the default:
ALTER SYSTEM SET dtl_compress_func = 'lz4_1.0';
-- Disable compression independently of the selected algorithm:
ALTER SYSTEM SET _px_message_compression = false;
```

The selection is captured when a DFC is initialized and is propagated to its
channels and broadcast services. A configuration update does not mutate existing
channels or provide an atomic, query-wide switch across observers. Packets from
old and new channels can coexist: the RPC header carries the actual codec ID
and original length, and the receiver decompresses by that header, not by its
current tenant setting. No enum values, RPC fields, or DTL serialization layouts
are added. A packet that does not shrink retains the existing raw-payload fallback.

This feature targets LakeBase `4.6.0.0` and later. Upgrades from earlier releases
are out of scope. The selected codec is not downgraded based on cluster version;
all allowed codecs are available in the supported baseline.
Both ZSTD wrappers use their existing fixed compression level (level 1).

## Build and run

From the repository root, follow the repository build wrappers:

```bash
bash build.sh init
bash build.sh release -DOB_USE_ASAN=OFF -DENABLE_BOLT=OFF
cd build_release
ob-make -j16 test_dtl_compression benchmark_dtl_compression
./unittest/sql/dtl/test_dtl_compression
cd unittest/sql/dtl
./benchmark_dtl_compression
ctest --output-on-failure -R '^test_dtl_compression_tpc_samples$'
```

The correctness tests cover the whitelist, disable-switch precedence, invalid
values, selection of all allowed codecs, tiny/random binary inputs, and the real RPC
receiver decoding single, one-/two-channel aggregate, control-batch and broadcast
arguments. Invalid lengths, truncated data and unknown codec IDs must fail.
Sender tests run the real serialization/compression path against a transport
without IO threads: posting fails intentionally, after compression, without
opening any network connections. Compression counters verify that normal,
control-batch and broadcast sends apply the selected setting. These are unit
tests, not a running-observer or mixed-binary deployment test.

## Reproducible TPC samples

The checked-in small corpus is generated with DuckDB 1.4.4's official
[TPC-H extension](https://duckdb.org/docs/current/core_extensions/tpch) and
[TPC-DS extension](https://duckdb.org/docs/current/core_extensions/tpcds),
SF 0.01, up to 256 rows per table. Its manifest records generator version,
row counts, file sizes and SHA-256 hashes. Values are synthetic, not customer data.
The benchmark runs offline against this corpus by default and verifies every
round trip; it has no timing-based pass/fail threshold.
It covers six tables, five settings and three chunk sizes (90 combinations),
including ZSTD 1.3.8. The archived 2026-09-11 report retains its existing
four-setting scope; its measurements are not regenerated by this change.
The build copies the corpus into `build_release/unittest/sql/dtl/compression_data`.
Run the benchmark from its binary directory, or set `DTL_COMPRESSION_DATA_DIR`
explicitly. CTest uses the binary directory and relative paths so the test and
its data remain usable after Farm relocates the unittest artifact.

For a larger sample, use a Python environment with `duckdb==1.4.4` installed:

```bash
python3 unittest/sql/dtl/generate_compression_data.py /data/tmp/dtl-tpc-corpus \
  --scale 0.1 --rows 65536
DTL_COMPRESSION_DATA_DIR=/data/tmp/dtl-tpc-corpus \
  ./build_release/unittest/sql/dtl/benchmark_dtl_compression
```

The generator refuses to overwrite a previous corpus. If extension downloads
are unavailable, pass `--extensions /path/to/signed/duckdb/extensions` containing
the matching `tpch.duckdb_extension` and `tpcds.duckdb_extension` files.

The tables are TPC-H `lineitem`, `orders`, `customer`, and TPC-DS `store_sales`,
`item`, `customer`. Sampling takes the first N rows after `ORDER BY ALL`; it is
deterministic, not random or representative of every SQL intermediate result.
The exported format is pipe-delimited CSV without a header. CSV encoding and
sorting affect compression, and the corpus must not be described as actual DTL
row encoding or an official/reportable TPC benchmark.

The benchmark calls OceanBase's real codec wrappers in 4 KiB, 64 KiB and 1 MiB
chunks, warms each chunk, then times five compression and five decompression
iterations with a monotonic clock. Throughput uses uncompressed input bytes.
`codec_bytes` is the raw codec output size; `payload_bytes` sums
`min(input_bytes, codec_bytes)` per block, modeling the RPC raw fallback.
`payload_pct` is payload bytes divided by input bytes (lower is smaller).
Sizes exclude RPC headers, transport framing and retransmissions. The `none`
wrapper is a no-op: its row reports 100% payload and `NA` for codec throughput.
These measurements compare codec CPU cost and compression ratio, not SQL latency,
end-to-end network bandwidth, or CPU savings from fewer transmitted bytes.
